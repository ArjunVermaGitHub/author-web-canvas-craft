# AGENTS.md

- Backend: Vercel serverless functions in `api/` (ES modules, `micro` buffer for body parsing, CORS headers on every response) backed by MongoDB Atlas via `MONGODB_URI` env and the cached connection in `api/utils/mongodb.js`. Do not add Lovable Cloud/Supabase — the user runs their own MongoDB. Why: user manages their own Vercel deployment and Atlas cluster.
- Prices and payee name live in `src/config/book.ts` as the single source of truth. Why: the user changes the book price when the Amazon price changes.
- Amazon stores live in `src/config/amazon.ts`; purchase buttons share browser-region selection and optional Meta click tracking through `src/lib/purchase.ts`. Why: all purchase placements must use consistent destinations without geo-IP requests or checkout changes.
- Owner-only tools live under /owner/* and call /api endpoints gated by the OWNER_ACCESS_CODE env var; AI calls run in Vercel functions using LOVABLE_API_KEY env. Why: no Lovable Cloud backend, keep keys server-side.
- Tracking comparison reuses the owner insights endpoint with a separately validated mode and server-only diagnostic prompt; shared pure comparison rules calculate ratios without inferring lost people. Why: matching report scope and owner access must be checked before paid AI requests.
- Keep quiz question data separate from its interactive component and build share links (author video embed, Pinterest pin) with pure URL helpers in `src/lib`; colocated Bun tests cover these rules. Why: scoring, embed visibility and share destinations remain independently verifiable.
- Store the sample PDF via Lovable Assets; preserve its existing public address with matching Vite-preview and Vercel redirects to the hosted asset. Why: existing reading links and welcome emails must continue to work without committing binary media.
- Use VideoFacade for trailer embeds, mounting third-party iframes only after activation without embed scripts. Why: video providers must not slow the initial page load.
- Use OrderBar at all homepage widths with shared PurchaseButtons and IntersectionObserver visibility; reserve bottom space at every width. Why: consistent ordering access must not cover the footer.
- Curated news lives in `src/data/indusNews.ts`; NewsSection loads live RSS results only on demand through the cached Vercel `api/news.js` endpoint, falling back to curated picks on failure. Keep plain page-flow link cards without inner scrolling, carousels, images, iframes or tracking. Why: preserve fast initial loading, safe external links and uninterrupted scrolling.
- Term explainers live in `src/data/wikiTerms.ts` and render as a plain page-flow list in WikiSection; the author extends the list by adding entries. Why: reader reference links stay data-only, testable and free of extra scripts.
- Community signup uses the shared Zod schema in `src/lib/communityValidation.js` in both the form and Vercel endpoint, with a unique email index in MongoDB. Why: client/server rules stay identical and concurrent signups cannot duplicate records.
- Pen-name catalogue data and menu entries live in `src/data/otherBooks.ts`; `/james-furrington` uses the shared Header/Footer and a linked pen-name note, with untracked catalogue links. The shared Header hides Raghav purchase buttons on pen-name routes via `shouldShowPurchaseButtons(pathname)` in `src/lib/headerPurchase.ts`. Optional store metadata selects edition labels and purchase wording (default Amazon.com); omit unconfirmed format/page metadata. Why: additional series stay data-driven without inventing listing details.
- Use HelmetProvider for route titles/descriptions/canonicals; mark the static homepage canonical with data-rh so Helmet replaces it rather than duplicates it, and keep static social tags as homepage fallback. Shared header anchors target the homepage from other routes. Why: route metadata must not retain a previous page's identity or ship duplicate canonicals.
- Keep Vite assets root-relative and preserve Vercel's filesystem/API rules before the SPA fallback. Why: refreshed nested page URLs must load assets without changing serverless endpoint behavior.
- Keep LPH stories, endings and book links in `src/data/alternateEndings.ts`; parameterized pages render only stories with available endings and reject unknown slugs. Hide Raghav header purchases for the entire `/lph` section through the shared header helper. The Other books menu lists LPH via `OTHER_BOOK_SERIES` and the Header highlights entries active under `/lph`. Why: legacy printed links remain valid and future stories require only data additions.
- Pen-name covers are optimized verified JPEGs stored via Lovable Assets with pointers in `public/books`; Vite and Vercel redirect `/books/<ASIN>.jpg` to those assets. Optional cover metadata supplies alt text and intrinsic dimensions. Why: preserve local image addresses without Amazon hotlinks or binary repository media.
- Campaign visits: UTM labels and a session ID live in sessionStorage via pure helpers in `src/lib/campaign.js`; `api/visits.js` stores one row per session in `rituraj-campaign-sessions` (unique sessionId) and returns grouped counts only to the owner. Why: refreshes and page changes must not inflate campaign counts.
- Order statuses (pending_verification/paid/cancelled), ID format and owner-code comparison live in `src/lib/orderStatus.js`; the order log and status changes are served only by owner-gated `api/owner-orders.js`. Why: order data must never reach a public endpoint and counts must exclude unpaid orders.
